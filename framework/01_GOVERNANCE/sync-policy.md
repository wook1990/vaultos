# Sync Policy

이 볼트는 Google Drive 위에 있고 여러 기기·여러 에이전트가 동시에 접근한다.
이 문서는 **무엇이 정본이고, 충돌을 어떻게 구조적으로 막는지**를 정한다.

## 1. 정본은 하나가 아니라 둘이다

| 대상 | 정본 | 왜 |
|---|---|---|
| VaultOS 문서 — 계약, 정책, 지식, 프로젝트 상태 | **Google Drive의 이 볼트** | 어느 기기에서도 같은 것을 본다 |
| 코드, 테스트, tracker yaml | **workspace git repo (GitHub)** | 병합·이력·충돌 해결이 필요하다 |
| API Key, Token, Credential | **Secret Manager / ENV** | 어느 쪽에도 두지 않는다 |

**"정본은 클라우드"는 볼트 문서에 대해서만 참이다.**
코드와 tracker를 Drive로 옮기면 Drive가 병합을 못 하기 때문에 곧바로 충돌이 나고, 결국 "볼트 사본 vs repo 원본" 중복이 되살아난다. 실제로 그렇게 됐던 사례가 [프로젝트 초기화 기록](https://github.com/<you>/vaultos/blob/main/docs/CASE-STUDY.md)에 있다 — 한 프로젝트의 `docs/` 88개 중 44개만, 그것도 넉 달 묵은 상태로 볼트에 복제돼 있었다.

### repo 주소는 URL이지 경로가 아니다

프로젝트의 `project.yaml`에는 **GitHub URL을 정본으로** 적는다.

```yaml
repo:
  url: https://github.com/<you>/my-app   # 정본. 어느 기기에서든 같다
  local:                                     # 기기별 편의 정보. 정본 아님
    wsl: /home/<you>/workspace/my-app
    mac: /Users/<you>/workspace/my-app
```

`/Users/...` 또는 `/home/...` 같은 **로컬 절대경로를 정본처럼 쓰지 않는다.**
그 기기에서만 유효하고, 다른 기기에서 열면 깨진 값이 된다. 기기가 바뀔 때 "옮겨야 하나"를 고민하게 되는 것 자체가 설계가 잘못됐다는 신호다.

repo는 옮기는 것이 아니라 **각 기기가 자기 자리에 clone하는 것**이다.

## 2. Drive의 물리적 성질 (정책의 근거)

Drive는 **동기화 도구이지 버전관리 시스템이 아니다.**

- 병합이 없다. 파일 단위 **마지막 저장자 우선(last-writer-wins)**이다.
- 두 기기가 같은 파일을 동시에 고치면 한쪽을 `파일명 (conflict 2026-04-21-19-48-33).md`로 만들어 **조용히 둘 다 남긴다.** 알림도 없다.
- 실제로 이 볼트에서 발생했던 일이다. 2026-04-21에 생성된 충돌 사본이 5개월간 방치돼 있었다.

따라서 이 정책의 목표는 충돌을 잘 해결하는 것이 아니라 **동시 쓰기가 구조적으로 일어나지 않게 만드는 것**이다.

## 3. 핵심 규칙 4개

### 규칙 1 — 한 파일은 한 기기에서만 쓴다

읽기는 여러 기기에서 동시에 해도 된다. **쓰기만 한 곳에서.**

### 규칙 2 — 기기를 바꿀 때는 쓰기 종료 → 동기화 완료 → 열기

```
A기기: 저장 → Obsidian 닫기 → Drive 아이콘이 "최신 상태"가 될 때까지 대기
B기기: 그 다음에 연다
```

Drive가 아직 올리는 중인데 다른 기기에서 열면 그 순간이 충돌 지점이다.

### 규칙 3 — 에이전트는 세션 경계에서만 쓴다

- 세션 시작: `resume` — 상태를 읽는다
- 세션 종료: `sync` — 한 번 쓴다
- **연속 자동 반영(`watch`)은 금지한다.** 이전 시스템이 이걸로 충돌을 만들었다.

상세: [[01_GOVERNANCE/agent-policy|Agent Policy]]

### 규칙 4 — 자주 바뀌는 기계 생성 파일을 볼트에 두지 않는다

빌드 산출물, 캐시, 렌더 로그, `node_modules`, 플러그인 임시파일. 이번 정리에서 66개를 제거했다.

## 4. 쓰기 빈도 등급 (충돌 위험 지도)

충돌 확률은 `동시 접근 가능성 × 쓰기 빈도 × 파일 수`에 비례한다. 세 값을 모두 낮게 유지한다.

| 등급 | 영역 | 실측 | 위험 |
|---|---|---|---|
| 거의 없음 | `00_SYSTEM`, `01_GOVERNANCE`, `04_AGENTS` | 48개 | 사람이 의도적으로 고칠 때만 바뀐다 |
| 낮음 | `03_KNOWLEDGE/20_permanent`, `references` | 163개 | 승격 시점에만 |
| 중간 | `03_KNOWLEDGE/00_inbox`, `10_fleeting` | 231개 | 캡처 자동화가 쓴다 — 단 **새 파일만 만들고 기존 파일을 고치지 않는다** |
| **높음** | `02_WORKSPACES/*/status/current-state.yaml` | **현재 0개** | 여러 에이전트가 같은 파일을 갱신할 수 있는 유일한 지점 |
| 무해 | `.obsidian/workspace.json` | 1개 | 세션 상태. 충돌 사본이 생기면 그냥 지운다 |

**이 표가 오늘 작업의 핵심 성과다.** 이전 구조는 프로젝트마다 `30_Tracking/` 미러 15개를 자동 생성해 "높음" 등급 파일이 프로젝트당 15개 이상이었다. 지금은 프로젝트당 **1개**다. 충돌 표면적 자체가 줄었다.

프로젝트를 다시 만들 때 이 숫자를 늘리지 않는 것이 이 정책의 실질적 내용이다.

## 5. 충돌 점검 루틴

주 1회 또는 기기를 오래 바꿔 쓴 뒤:

```sh
find . -iname "*conflict*" -not -path "./99_ARCHIVE/*"
```

충돌 사본을 찾으면:

1. 원본과 내용을 비교한다
2. 필요한 내용을 원본에 합친다
3. 사본을 지운다
4. 왜 동시에 썼는지 확인한다 — 반복되면 규칙 1~2가 지켜지지 않고 있다는 뜻이다

`.obsidian/workspace.json`의 충돌 사본은 비교 없이 지워도 된다.

## 6. 백업과 롤백

**이 볼트에는 git을 쓸 수 없다.** WSL의 9p 마운트가 `chmod`를 지원하지 않아 `git init` 자체가 실패한다.

볼트 안에 `.git`을 두는 것은 Mac에서 가능하더라도 **권장하지 않는다.** Drive가 `.git` 내부 파일을 동기화하다가 두 기기가 경쟁하면 저장소가 깨질 수 있다. 얻는 것(마크다운 라인 단위 병합)보다 잃을 수 있는 것이 크다.

대신 **tar 스냅샷**을 쓴다. 위치: `99_ARCHIVE/_backups/`

| 시점 | 대상 |
|---|---|
| 구조를 바꾸기 전 | 볼트 전체 |
| 대량 삭제 전 | 최소한 삭제 대상 영역 |
| 주 1회 | 볼트 전체 |

개별 파일 실수는 **Drive 웹의 버전 기록**으로도 되돌릴 수 있다(파일 단위, 30일).
대량 사고는 tar에서 복원한다.

## 7. 볼트에 두지 않는 것

| 대상 | 어디에 |
|---|---|
| 코드, 테스트, tracker yaml | workspace git repo |
| 빌드 산출물, 캐시, 렌더 로그 | 어디에도 두지 않는다 |
| API Key, Password, Token | Secret Manager / ENV. 문서에는 **참조만** |
| 회사 CONFIDENTIAL 이상 자료의 외부 전송 | 승인 항목 → [[01_GOVERNANCE/approval-policy\|Approval Policy]] |

## 8. 캡처 자동화

```
Telegram → Google Apps Script → Google Drive → 03_KNOWLEDGE/00_inbox/ → Drive for desktop → Obsidian
```

Apps Script는 Drive API로 **직접** 쓰므로 로컬 기기의 Obsidian과 경쟁하지 않는다.
단 현재 설계의 두 조건을 유지한다.

- **새 파일만 만든다.** 기존 노트를 수정하거나 삭제하지 않는다
- 같은 webhook이 재전송돼도 같은 파일을 다시 만들지 않는다 (update_id 기반 중복 방지)

상세: [[00_SYSTEM/conventions|Conventions]]

## 9. 한 줄 요약

> Drive는 **어느 기기에서든 같은 것을 보게 해주는 전송 수단**이고, git은 **여럿이 같은 것을 고칠 때 합쳐주는 수단**이다.
> 문서는 Drive에, 코드는 git에 둔다. 그리고 **같은 파일을 두 곳에서 동시에 쓰지 않는다.**
